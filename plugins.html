Plugin Development Guide

API version 1

What a plugin is

An rssh plugin is a zip: a manifest.json and one self-contained index.html. rssh loads it into a sandboxed iframe docked to one of two regions around your terminal — the side column or the strip bar.

A plugin has exactly one capability: exec — run a command on the machine of the current tab and get {stdout, stderr, exitCode} back. Monitoring dashboards, service controls, log viewers — everything is built from that.

Package layout

my-plugin.zip
├── manifest.json     required, at the zip root
├── index.html        required, the whole UI
└── assets/**         optional

manifest.json

{
  "id": "hello-world",
  "name": "Hello World",
  "version": "1.0.0",
  "description": "Runs one command and shows the output",
  "author": "you",
  "area": "side",
  "api": 1
}
FieldNotes
idSlug ^[a-z0-9-]{2,64}$. Doubles as the install directory; reinstalling the same id upgrades in place.
name / version / description / author Shown in the plugin manager.
area"side" or "strip" — which region the plugin docks to. The backend rejects a zip installed from the other region's button.
apiMust be 1.

The bridge (API v1)

The iframe talks to rssh over postMessage. This is the whole protocol:

DirectionMessageMeaning
plugin → host{v:1, id, cmd:"exec", payload:{command, timeoutMs?}} Run a command.
host → plugin{v:1, id, ok:true, result:{stdout, stderr, exitCode}} Exec finished.
host → plugin{v:1, id, ok:false, error:{code, message}} Exec failed.
plugin → host{v:1, id, cmd:"size", payload:{width?, height?}} Report your natural size (notification, no reply).
host → plugin{v:1, evt:"hello", payload:{apiVersion, theme}} Fired once on load.
host → plugin{v:1, evt:"visibility", payload:{visible}} Your tab switched away / came back.

A minimal client is ~30 lines of vanilla JS — no SDK required:

let seq = 0;
const pending = new Map();

window.addEventListener("message", (e) => {
  const m = e.data;
  if (!m || m.v !== 1) return;
  if (m.evt === "hello") applyTheme(m.payload.theme);
  if (m.evt === "visibility") setVisible(m.payload.visible);
  if (m.id && pending.has(m.id)) {
    const {resolve, reject} = pending.get(m.id);
    pending.delete(m.id);
    m.ok ? resolve(m.result) : reject(m.error);
  }
});

function exec(command, timeoutMs) {
  const id = "q" + (++seq);
  return new Promise((resolve, reject) => {
    pending.set(id, {resolve, reject});
    parent.postMessage({v: 1, id, cmd: "exec",
                        payload: {command, timeoutMs}}, "*");
  });
}

function applyTheme(tokens) {  // match rssh's look in both themes
  for (const [k, v] of Object.entries(tokens ?? {}))
    document.documentElement.style.setProperty(k, v);
}

exec() resolves with {stdout, stderr, exitCode} or rejects with {code, message}. Error codes you will actually see: plugin_no_exec (the tab has no exec channel — telnet/serial), plugin_exec_timeout, plugin_busy.

Events

  • hello — arrives once after load. theme carries rssh's design tokens (--bg, --text, --accent, …); apply them as CSS custom properties and your UI matches the app for free.
  • visibility — the iframe is keep-alive across tab switches, so this is how you learn you went to the background. Pause polling while hidden.

Sizing your panel

The sandbox stops rssh from measuring iframe content — only you know your natural size. Side plugins report their height, strip plugins their width:

parent.postMessage({v: 1, id: "s1", cmd: "size",
                    payload: {height: 140}}, "*");

Limits

WhatLimit
Command length4 KB
Concurrent execs per plugin4 (excess gets plugin_busy)
Timeoutclamped to 1–60 s, default 10 s
stdout / stderr256 KB each
Zip10 MB, ≤ 500 files, no symlinks / .. / absolute paths

Security model

  • The iframe runs sandbox="allow-scripts" — an opaque origin. It cannot read rssh's DOM or storage and cannot invoke Tauri commands.
  • The host brokers every exec and never hands the plugin a session id.
  • Commands run as your SSH user, on the machine the current tab is connected to. Installing a plugin means trusting its commands — the same trust as installing a shell script. v1 has no permission matrix or signatures.
  • The sandbox has no localStorage. Want config persistence? Store it on the server — echo > ~/.config/my-plugin.json is one exec away.

Where commands run

Tabexec runs on
SSHthe remote machine, over your connection
Local shellthis machine (a fresh child process per call)
Telnet / serialno exec — plugin_no_exec

The plugin never branches on this. The same zip monitors a remote Linux box from an SSH tab and your laptop from a local shell tab.

Case study: rssh-plugin-monitor

github.com/rssh-org/rssh-plugin-monitor is the reference implementation — two plugins sharing one SDK:

sdk/            shared, dependency-free library
  host.ts       bridge client: exec / onVisibility / autoSize / theme
  metrics.ts    probe commands + /proc & macOS parsers (pure, tested)
  poller.ts     poll loop: pause-on-hidden, backoff-on-error
  ring.ts       fixed-length sparkline buffer
plugins/
  icons-monitor/   side region: canvas sparklines + disk bars
  text-monitor/    strip region: one monospace text line
  • One exec per poll. Five probes (/proc/stat, /proc/meminfo, /proc/loadavg, /proc/net/dev, df -Plk) joined into a single shell line with __RSSH_*__ markers, parsed client-side — one round-trip.
  • Platform probe. The first poll runs uname -s: Linux reads /proc, macOS falls back to vm_stat/sysctl/netstat, anything else reports unsupported.
  • Counter diffing. CPU and network counters are cumulative since boot; the poller keeps the previous snapshot and diffs.
  • Lifecycle discipline. 3 s poll, stops on visibility: false, backs off on error.
  • Single-file packaging. Vite + vite-plugin-singlefile inlines everything into index.html; scripts/package.mjs zips it with the manifest.

Case study: rssh-plugin-mascot

github.com/rssh-org/rssh-plugin-mascot is the other end of the spectrum — a purely visual strip plugin that never calls exec:

  • One hand-written index.html. No build step, no SDK, no dependencies — a canvas pixel cat, a small behavior state machine, and ~30 lines of bridge code.
  • Theme and lifecycle only. It consumes hello (recolors the cat from the theme tokens) and visibility (stops all timers when its tab is hidden); the only message it sends is size.
  • Content-driven size. The body is shrink-wrapped (width: fit-content) and a ResizeObserver reports the measured width — the segment breathes with the speech text and collapses after it fades.

Packaging and installing

  • Build to a single index.html (vite-plugin-singlefile, or just write it by hand). The zip should have no cross-file path dependencies.
  • Zip manifest.json + index.html (+ optional assets/).
  • Install: Settings → Plugins → the install button of the region your area declares. Reinstalling the same id upgrades in place.

插件开发指南

API 版本 1

插件是什么

rssh 插件就是一个 zip：一份 manifest.json 加一个自包含的 index.html。rssh 把它装进沙箱 iframe，停靠在终端周围两个区域之一 —— 侧栏（side column）或横条（strip bar）。

插件只有一项能力：exec —— 在当前标签页连接的机器上跑一条命令， 拿回 {stdout, stderr, exitCode}。监控面板、服务控制、日志查看器， 全都由它长出来。

包结构

my-plugin.zip
├── manifest.json     必需，zip 根目录
├── index.html        必需，整个 UI
└── assets/**         可选

manifest.json

{
  "id": "hello-world",
  "name": "Hello World",
  "version": "1.0.0",
  "description": "Runs one command and shows the output",
  "author": "you",
  "area": "side",
  "api": 1
}
字段说明
idslug ^[a-z0-9-]{2,64}$，同时是安装目录名； 重复安装同 id = 原地升级。
name / version / description / author 展示在插件管理页。
area"side" 或 "strip"，声明停靠区域； 从另一个区域的安装入口装会被后端拒绝。
api必须是 1。

桥协议（API v1）

iframe 与 rssh 之间走 postMessage。协议全部内容如下：

方向消息含义
插件 → 宿主{v:1, id, cmd:"exec", payload:{command, timeoutMs?}} 跑一条命令。
宿主 → 插件{v:1, id, ok:true, result:{stdout, stderr, exitCode}} 执行完成。
宿主 → 插件{v:1, id, ok:false, error:{code, message}} 执行失败。
插件 → 宿主{v:1, id, cmd:"size", payload:{width?, height?}} 上报自身尺寸（通知，无回复）。
宿主 → 插件{v:1, evt:"hello", payload:{apiVersion, theme}} 加载后发一次。
宿主 → 插件{v:1, evt:"visibility", payload:{visible}} 所在标签页切走 / 切回。

一个最小客户端 30 行原生 JS 就够，不需要 SDK：

let seq = 0;
const pending = new Map();

window.addEventListener("message", (e) => {
  const m = e.data;
  if (!m || m.v !== 1) return;
  if (m.evt === "hello") applyTheme(m.payload.theme);
  if (m.evt === "visibility") setVisible(m.payload.visible);
  if (m.id && pending.has(m.id)) {
    const {resolve, reject} = pending.get(m.id);
    pending.delete(m.id);
    m.ok ? resolve(m.result) : reject(m.error);
  }
});

function exec(command, timeoutMs) {
  const id = "q" + (++seq);
  return new Promise((resolve, reject) => {
    pending.set(id, {resolve, reject});
    parent.postMessage({v: 1, id, cmd: "exec",
                        payload: {command, timeoutMs}}, "*");
  });
}

function applyTheme(tokens) {  // 跟随 rssh 的明暗主题
  for (const [k, v] of Object.entries(tokens ?? {}))
    document.documentElement.style.setProperty(k, v);
}

exec() 成功返回 {stdout, stderr, exitCode}，失败抛 {code, message}。常见的错误码：plugin_no_exec （该类标签页没有 exec 通道，如 telnet/serial）、plugin_exec_timeout、 plugin_busy。

事件

  • hello —— 加载后发一次。theme 携带 rssh 的设计令牌 （--bg、--text、--accent 等），按 CSS 自定义属性套上，UI 就自动跟随应用主题。
  • visibility —— iframe 在标签页切换间保活，靠这个事件得知自己 进了后台。不可见时请停止轮询。

上报尺寸

沙箱导致宿主量不到 iframe 内容 —— 只有你自己知道自然尺寸。侧栏插件报高度、 横条插件报宽度：

parent.postMessage({v: 1, id: "s1", cmd: "size",
                    payload: {height: 140}}, "*");

限制

项目上限
命令长度4 KB
单插件并发 exec4（超出收到 plugin_busy）
超时钳制在 1–60 秒，默认 10 秒
stdout / stderr各 256 KB
zip 包10 MB、≤ 500 个文件、拒绝符号链接 / .. / 绝对路径

安全模型

  • iframe 以 sandbox="allow-scripts" 运行 —— 不透明 origin， 读不到 rssh 的 DOM 和存储，调不了 Tauri 命令。
  • 每次 exec 都由宿主代理，插件永远拿不到 session id。
  • 命令以你的 SSH 用户身份、在当前标签页连接的机器上执行。 装一个插件 = 信任它跑的命令，和装一个 shell 脚本同一级别的信任。 v1 没有权限矩阵、没有签名。
  • 沙箱里没有 localStorage。需要持久化配置？存到服务器上 —— echo > ~/.config/my-plugin.json 一次 exec 的事。

命令在哪台机器上跑

标签页exec 执行位置
SSH远端机器，走当前连接
本地 shell本机（每次调用一个全新子进程）
Telnet / serial没有 exec —— plugin_no_exec

插件代码对此零分支：同一个 zip，在 SSH 标签页监控远端 Linux，在本地 shell 标签页监控你手上的这台机器。

案例：rssh-plugin-monitor

github.com/rssh-org/rssh-plugin-monitor 是参考实现 —— 两个插件共享一套 SDK：

sdk/            共享零依赖库
  host.ts       桥客户端：exec / onVisibility / autoSize / theme
  metrics.ts    探测命令 + /proc 与 macOS 解析器（纯函数，带测试）
  poller.ts     轮询循环：不可见即停、出错退避
  ring.ts       定长火花线缓冲
plugins/
  icons-monitor/   侧栏区：canvas 火花线 + 磁盘条
  text-monitor/    横条区：一行等宽文字
  • 每次轮询只花一次 exec。五个探测（/proc/stat、 /proc/meminfo、/proc/loadavg、/proc/net/dev、 df -Plk）用 __RSSH_*__ 标记拼成一条 shell 命令， 客户端解析 —— 一个来回。
  • 平台探测。首次轮询先跑 uname -s：Linux 读 /proc，macOS 退到 vm_stat/sysctl/netstat， 其余平台显示不支持。
  • 计数器差分。CPU 和网络计数器是开机以来的累计值， 轮询器保存上一拍快照做差分。
  • 生命周期纪律。3 秒一轮；visibility: false 即停； 出错退避。
  • 单文件打包。Vite + vite-plugin-singlefile 把所有产物内联进 index.html，scripts/package.mjs 连同 manifest 一起打成 zip。

案例：rssh-plugin-mascot

github.com/rssh-org/rssh-plugin-mascot 是另一个极端 —— 纯视觉横条插件，从不调用 exec：

  • 一个手写的 index.html。没有构建、没有 SDK、 没有依赖 —— 一只 canvas 像素猫、一个小型行为状态机、约 30 行桥代码。
  • 只用主题和生命周期。消费 hello（按主题色重绘猫） 与 visibility（所在标签页隐藏即停掉全部定时器）； 对外只发 size 一条消息。
  • 量内容报尺寸。body 收缩包裹（width: fit-content）， ResizeObserver 上报实测宽度 —— 段宽随台词呼吸，淡出后收回。

打包与安装

  • 构建成单个 index.html（vite-plugin-singlefile，或直接手写）。 zip 内不要有跨文件路径依赖。
  • 把 manifest.json + index.html（可加 assets/）打成 zip。
  • 安装：设置 → 插件 → 点与 area 对应区域的安装按钮。 重复安装同 id 为原地升级。
